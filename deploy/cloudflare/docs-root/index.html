A self-hosted home for your arsenal of models.

Hangar is a Hugging Face Hub-compatible server for your machine learning models and datasets. Pull from huggingface.co once, keep full version history on your own storage, and serve it to the tools you already use.

How it works

Pull once. Load from your own storage as often as you like.

  1. Discover

    Search huggingface.co, or another Hangar Instance, from the web UI or the hangar CLI. What is already in your Arsenal is marked.

  2. Pull

    Fetch a whole Repo, or only the quantisation, Config or Split you want, with any code it depends on. Pulls run as background Jobs, inside pull windows if your bandwidth needs them.

  3. Serve

    A Mirror keeps the upstream Repo ID and Commit SHAs, so pinned Revisions keep working. Clients load from fast local storage, even on an air-gapped network.

Operate

From a laptop to a cluster

Start with one container and grow into a highly available deployment without changing how clients connect.

Start small

1 container · SQLite · a local folder

Run Hangar on a laptop, a homelab or a single VM with Docker, Docker Compose or one binary for Linux, macOS or Windows.

Scale out

Replicas · Postgres · S3-compatible storage

Run stateless replicas with separate web and worker processes, installed with the Helm chart. See Scaling.

  • Sign in with your identity provider

    Local accounts and OIDC, with guides for Keycloak, Authentik, Microsoft Entra ID, Google, Okta and GitLab.

  • Organisations, Roles and Tokens

    Share Repos with read, write and admin Roles, and give each client a scoped Token with an optional expiry.

  • Security scans

    Every Commit is scanned for pickle files that run code when loaded, and you choose what to block.

  • OpenTelemetry built in

    Traces, metrics and logs, with ready-made Grafana and Kibana dashboards.

  • Webhooks and Collections

    React to pushes and Pulls with webhooks, and curate ordered Collections of Repos for your team.

  • Import what you already have

    Bring an existing Hugging Face cache into Hangar, and back up and restore an Instance when you need to.

Quickstart

Start with one command

Run the container, then sign in. Compose, Helm and binary installs are in Get started. 

docker run -d --name hangar -p 8080:8080 -v hangar:/var/lib/hangar \
  -e HANGAR_SERVER_PUBLIC_URL=http://localhost:8080 \
  ghcr.io/hangar-hub/hangar:latest
docker logs hangar
  1. docker logs prints the generated admin password and Instance key once.
  2. Open http://localhost:8080, sign in as hangar-admin, and pull a model from Discover.
  3. Set HF_ENDPOINT and HF_TOKEN, and load it with the tools you already use.

Questions

Frequently asked questions

Does Hangar run models?

No. Hangar stores and serves files. Run models with the tools you already use, such as transformers, vLLM, Ollama or LM Studio, and point them at Hangar for the weights. Spaces and the Inference API are out of scope.

Do I need to change my code?

No. Set HF_ENDPOINT to your Instance and HF_TOKEN to a Token you create in Hangar. huggingface_hub, the hf CLI, transformers, diffusers, sentence-transformers, datasets and vLLM then work unchanged.

Can Hangar run without internet access?

Yes. An air-gapped Instance can pull from another Hangar Instance that has internet access, as its Upstream. You can also import an existing Hugging Face cache.

Does it work with hf_xet?

Yes for uploads. Hangar accepts Xet uploads, so huggingface_hub with hf_xet installed works with no setup. It stores whole files and serves them over plain HTTP.

What does it cost?

Nothing. Hangar is source-available under the Elastic License 2.0. You can use, change and self-host it, including inside your company. You can't offer it to others as a hosted or managed service, or remove licence notices.
